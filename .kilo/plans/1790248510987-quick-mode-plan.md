# Plan: Modo Rápido vs Modo Completo al abrir la app

## Objetivo

Al abrir la app (tras autenticación) se muestra **siempre** una pantalla de selección con dos opciones:

- **Modo completo**: la app actual, sin cambios.
- **Modo rápido**: pantalla minimalista tipo "Hoy" en una tarjeta centrada estrecha (~440px), con Siguiente foco, Tareas de hoy, Atrasadas, Próximas tareas y Agenda/Eventos (solo lectura), alta de tareas con mini-formulario básico, y un link para saltar al modo completo.

## Decisiones tomadas (con el usuario)

| Decisión | Resultado |
|---|---|
| Frecuencia del selector | **Siempre** al abrir la app. Sin persistencia (el modo vive en memoria, `useState`). Recargar = selector de nuevo. |
| Implementación | **Vista dentro del SPA** (sin segundo HTML, sin router, sin cambios en SW/manifest). Respeta estado centralizado en `App.jsx`. |
| Formato | Tarjeta centrada estrecha (max-width ~440px), densidad compacta, sin header ni BottomNav. |
| Secciones modo rápido | Siguiente foco (compacto) + Tareas de hoy + Atrasadas + Próximas tareas + Agenda/Eventos. |
| Acciones sobre tareas | **Solo completar** (checkbox → `toggleDone` existente). Editar/cambiar status/borrar → modo completo. |
| Añadir tarea | **Mini-formulario con campos**: nombre (requerido) + fecha (default hoy) + prioridad (pills, default `medium`). Sin NLP, sin IA. |
| Eventos | **Solo lectura** (agenda del día). |
| Volver a modo rápido desde completo | **Botón fijo en el header** (desktop y mobile). |
| Destino del link "versión completa" | Vista **Hoy** (`view='today'`). |

## Diseño técnico

### Estado nuevo en `App.jsx`

```js
const [uiMode, setUiMode] = useState(null); // null = selector | 'full' | 'quick'
```

- No se persiste en localStorage (decisión: selector siempre).
- `enterFullMode()` → `setUiMode('full'); navigateToView('today')`.
- `enterQuickMode()` → `setUiMode('quick')`.

### Árbol de render (App.jsx, tras los gates existentes)

```
authenticated === null  → splash (sin cambios)
!authenticated          → Login (sin cambios)
uiMode === null         → <ModeSelector onSelect={enterFullMode|enterQuickMode} />
uiMode === 'quick'      → <QuickModeView ... /> (+ ToastContainer)
uiMode === 'full'       → shell actual (header + vistas + BottomNav + modales)
```

- El modo rápido se renderiza **dentro de App.jsx**, por lo que todos los efectos (sync, `checkSession`, online/offline) y handlers (`toggleDone`, `upsert`) siguen activos sin duplicación.
- Los modales/drawers del shell completo (TaskSheetDrawer, CommandMenu, SettingsModal…) solo se montan en `full`. `ToastContainer` debe estar disponible también en `quick` (feedback de completar/crear y errores de sync).
- `forceLogout` / cambio de sesión siguen funcionando: al expirar sesión en modo rápido se vuelve a Login (flujo existente).

### Componente nuevo: `src/components/ModeSelector.jsx`

- Pantalla completa centrada con dos tarjetas-botón grandes:
  - "Modo completo" — descripción: "Todas las vistas y funciones".
  - "Modo rápido" — descripción: "Tu día de un vistazo".
- Botones reales (`<button>`), focus visible, primer botón con autofocus. Sin estado, sin persistencia.
- Estilos en el nuevo `src/components/QuickModeView.css` (mismo archivo, siguiendo el precedente de `GraphView.css` / `TimelineView.css`).

### Componente nuevo: `src/components/QuickModeView.jsx` (+ `QuickModeView.css`)

Tarjeta centrada `.quick-mode-shell` (max-width ~440px, centrada, padding, tokens M3 existentes) con `data-density="compact"` en el contenedor para heredar las reglas compactas ya definidas en `index.css`. Reutilizar clases de TodayView (`today-task-card`, `today-stat-pill`, etc.) donde sea posible.

**Props (todas ya disponibles/calculadas en App.jsx):**

```js
{
  todayTasks, overdueTasks, upcomingTasks, todayEvents,
  focusTasks,                 // para recommendNextFocusTask (igual que TodayView)
  statuses,
  nextFocusAllowedStatuses,
  onToggleComplete,           // toggleDone existente
  onCreateTask,               // helper nuevo en App.jsx (ver abajo)
  onSwitchToFull,             // enterFullMode
}
```

**Secciones (en orden):**

1. **Header compacto**: fecha de hoy + link/botón "Versión completa →" (`onSwitchToFull`).
2. **Siguiente foco** (compacto): `recommendNextFocusTask({ tasks: focusTasks, today, now, statuses, allowedStatuses: nextFocusAllowedStatuses })` — mismo patrón que `TodayView.jsx` líneas 98-110. Nombre + reason pill + checkbox completar. Sin dropdown de status ni botón editar.
3. **Añadir tarea** (mini-formulario): input nombre (required, autofocus opcional), input `type="date"` (default `todayStr`), pills de prioridad (`low/medium/high/critical`, default `medium`), botón "Añadir". Tras crear: reset del form (fecha vuelve a hoy, prioridad a medium) y focus de vuelta al input nombre.
4. **Tareas de hoy**: lista con checkbox; empty state "Sin tareas para hoy".
5. **Atrasadas**: igual, solo si hay.
6. **Próximas tareas**: grupos por fecha (reusar markup/clases de `upcoming-tasks-subblock` de TodayView).
7. **Agenda y eventos**: `todayEvents` en solo lectura (hora + título + color). Sin crear ni editar.

**Sin scroll propio de página**: la tarjeta crece con el contenido; scroll natural del body. No hay acciones de editar/borrar/reordenar.

### Helper de creación en `App.jsx`

```js
const handleQuickModeCreate = ({ name, date, priority }) =>
  upsert({ name: name.trim(), date, time: '', status: 'not_done',
           priority, subtasks: [], category: '', url: '', notes: '' });
```

Reutiliza `upsert` (línea ~1055) → sync debounced + persistencia local automáticos. Validación mínima: ignorar si `!name.trim()`.

### Botón "Modo rápido" en el header (modo completo)

- `IconButton` con `aria-label="Modo rápido"` en el header, visible en desktop y mobile (junto a los controles existentes del header; BottomNav sin cambios).
- Icono: usar uno existente del sprite `public/icons.svg` tipo rayo/velocidad si existe; si no, añadir un símbolo `#icon-bolt` al sprite.
- Handler: `setUiMode('quick')` (mantiene `view` actual; al volver a completo desde rápido se entra en `today` por decisión del link).

### Sync / offline / PWA

- Sin cambios en `worker.js`, `storage.js`, `public/sw.js`, `manifest.json`, `vite.config.js`.
- Completar/crear en modo rápido pasa por los mismos handlers → sync y offline-first intactos.
- Focus mode activo se respeta (se usan los mismos `focusTasks` derivados que TodayView).

## Riesgos y edge cases

- **E2E existentes rotos** por el selector siempre visible → mitigado con el helper `enterFullMode` en el `beforeEach` (tarea 5, hacerlo primero al implementar).
- **Sesión expira en modo rápido**: flujo existente de `forceLogout` cubre el caso; se muestra Login y al re-entrar aparece el selector (consistente con "mostrar siempre").
- **Cambio de workspace**: no hay selector de workspace en modo rápido (by design, minimalista). El modo se mantiene si se cambiara desde otro sitio; sin acción requerida.
- **Logout desde modo rápido**: no hay botón de logout en la tarjeta (recargar → selector → modo completo). Fuera de scope.
- **Undo**: completar/crear no registran undo hoy; se mantiene ese comportamiento.
- **Fecha del mini-form en el pasado**: permitido (cae en "Atrasadas"), mismo criterio que el resto de la app.
- **Accesibilidad**: tarjetas del selector como `<button>`, `aria-label` en el botón del header, landmarks (`<main>`) en `QuickModeView`, focus al contenedor al entrar en cada modo.

## Fuera de scope

- Persistencia de la elección de modo (decidido: siempre mostrar selector).
- Edición de tareas/eventos, cambio de status, borrado y creación de eventos en modo rápido.
- Entrada HTML separada (`quick.html`), cambios en SW/manifest, deep-linking.
- Comando en Command Menu para cambiar de modo (se usa botón fijo en header).
